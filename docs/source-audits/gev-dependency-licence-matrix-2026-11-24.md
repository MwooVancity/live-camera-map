# GEV dependency and external-host licence matrix, 2026-11-24

Purpose: code licence (MIT) is not data, imagery or API licence. This lists every npm runtime dependency, and every external host, API, tile service, model, font and dataset the unmodified GEV app (`gev/`) contacts or bundles, with the commercial ad-supported verdict. Read-only audit: nothing in `gev/` was touched, no git was run, the app was not started.

Method and limits (all VERIFIED unless a cell says otherwise):
- Dependencies: `gev/package.json` plus the `license` field of each `gev/node_modules/<pkg>/package.json` (read 2026-11-24).
- Hosts: grep of `gev/src`, `gev/server`, `gev/index.html`, `gev/public` for https hosts, then the code that uses the top ones read. GEV's own `gev/DATA_SOURCES.md` and `gev/.env.example` read for the licence statements. DATA_SOURCES.md is GEV's claim, so a licence taken only from it is labelled UNVERIFIED.
- Official terms pages fetched ONCE each with curl (User-Agent `worldtrafficcameras-research`, no login, no key) on 2026-11-24. Quotes below are from those pages. A page that could not be read says so.
- Our side read from: `data/proxy-allowlist.json`, `data/exclusion-map.json`, `data/source-permissions.json`, `ops/deploy/gev-exclusion.env`, `site/src/lib/map-params.mjs`, `plan.md` item 25.
- Verdict words: ALLOWED, ALLOWED WITH CREDIT, NEEDS WRITTEN PERMISSION, NOT ALLOWED, UNKNOWN. Last column label: VERIFIED = I read the file or page that decides it; UNVERIFIED = only a secondary statement (GEV doc, our own permission row); UNKNOWN = not read.

## C. Key questions

1. Which hosts can a visitor's browser reach directly, that our nginx proxy cannot block?
Every row marked BROWSER-DIRECT: B01 Esri, B02-B04 Cesium ion, Bing and World Terrain (only with a token), B05 and B06 Google (only with a key), B07 OSM tiles, B08 OpenFreeMap, B09 NASA GIBS and CMR, B10 Mapterhorn terrain, B11 Mapillary, B12 Panoramax, B13 KartaView, B24 Google Fonts, B26 Photon, B27 Planespotters, B28 Open Vessel Photos, B29 ALPR tiles, B30 ECCC, B31 GBIF, B32 the library tile hosts, B35 YouTube, and each radio stream host (B22). The page itself is served by our proxy, but these requests go from the visitor to the provider, so `data/proxy-allowlist.json` cannot stop them. GEV's own CSP (`gev/build/vite.js` lines 69-88, VERIFIED) is wide open: `img-src 'self' data: blob: https:` and `connect-src 'self' blob: data: https: wss: ws:`. A second CSP header from nginx is the only enforcement point (plan item 25).

2. Can a visitor switch the basemap to Esri in GEV's UI?
Yes. `MAP_STACKS` in `gev/src/maps/catalog.js:31` lists `esri-imagery` ("Esri Satellite", chip "SAT"); it is offered as a chip (`mapStackChips.js:20`), by the omnibar (`omnibarIntent.js:29`, any text matching "esri" or "satellite imagery"), by a share-link hash (`map=esri-imagery`, accepted in `share/viewCodec.js:114`), and by stories and scenes (`shotPresentation.js:106,113`, `stories/controller.js:823`). Our `map=osm` hash only sets the first view.

The one safest mechanism without editing GEV: an nginx-added second `Content-Security-Policy` header (two enforced CSPs intersect) on the `/map/` iframe document and its GEV assets, whose `connect-src` and `img-src` omit `services.arcgisonline.com` (and `server.arcgisonline.com`). This works because GEV fetches Esri with `fetch` (connect-src) in `globeEngine.js:68-83`, and the code comment says "a refused tile is a failed one, which counts toward the Esri source's fallback to OSM" (VERIFIED in the comment; the fallback itself is NOT yet tested with the CSP in place). It needs a real browser run to prove Esri = 0 requests, and an allow-list built from a real network log (MapLibre workers, blob URLs). Query-parameter, hash or allowlist changes alone cannot do it: the hash is user-editable, and the proxy never sees the browser-to-Esri traffic.
